# Code Review — Issue #559

| Dimension | Finding | Severity | Action |
| --- | --- | --- | --- |
| API surface | Production code retained a public helper that silently created relationship types. | High | Removed `KnowledgeGraph::ensure_relationship_type` and its transactional counterpart; seeded runtime callers now use the closed-taxonomy resolver. |
| Test infrastructure | Existing tests relied on implicit auto-creation and would lose arbitrary fixture vocabulary without a production helper. | Medium | Added a non-emitting relationship-type fixture helper to the already test-only `mimir-test-support` crate and routed test/benchmark callers through it. |
| Security | Direct fixture SQL could theoretically create runtime vocabulary if the helper leaked into production code. | Medium | Kept the helper in `mimir-test-support`, which is only available through dev-dependencies, and verified the production dependency graph does not include it. |
| Correctness | Reconciliation tests depended on the exact legacy auto-created description. | Low | Updated reconciliation tests to create legacy-style fixtures locally while general test fixtures remain distinctly marked as test-only. |
| Correctness | The fixture helper could leave a row without its self-alias if the two writes were interrupted. | Low | Wrapped type creation and self-alias registration in one transaction. |
| DRY compliance | The fixture helper duplicated relationship-name normalization from `mimir-knowledge`. | Low | Reused the crate's read-only lookup for alias resolution and made the fixture helper accept only already-normalized test names. |
| Documentation | Schema, tooling, closed-taxonomy, and wiki documentation still described auto-creation as supported. | Low | Replaced stale API guidance with the strict lookup/governance model and added the issue-specific test-only fixture boundary. |
| Naming | Test names and comments still referred to the removed public API. | Low | Renamed affected tests to describe the test fixture and updated related assertions/comments. |
| Compliance | A release version increment was required. | Low | Bumped the workspace version to `0.163.0` for the pre-1.0 breaking removal of a public knowledge-graph API; the repository deliberately keeps no separate changelog file, so release notes are generated by the existing release tooling. |

Final review result: zero open findings.
