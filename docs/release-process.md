# Release Process

## Overview

Mimir has no CI/CD pipeline: a release is a local, one-command step. `scripts/new-release.sh` reads the version, creates an annotated tag, pushes it, and publishes a GitHub release via the `gh` CLI, with the release body generated by GitHub from the commits since the previous release. The repository keeps no changelog file; the full recent release history lives on [GitHub Releases](https://github.com/BhavsarDevansh/Mimir/releases), and versions before 0.152.2 (which predate the GitHub-release workflow) are preserved in `CHANGELOG-archive.md`.

## Before releasing

1. Bump the version in the root `Cargo.toml` `[workspace.package]` table only; every workspace member inherits it via `version.workspace = true`.
2. Update `docs/` and `docs/wiki/` and run the code review per AGENTS.md; the release script itself is unit-tested by `scripts/tests/new-release_test.sh`.

## Releasing

`scripts/new-release.sh [--dry-run] [--version VER] [VERSION]`:

- The version defaults to the root `Cargo.toml` version; `--version VER` or a positional VERSION overrides it.
- The release body is generated by GitHub from the commits since the previous release; set `$RELEASE_NOTES_FILE` to a file of hand-written notes to publish exactly those instead. The script refuses to publish when the version is malformed, the tag `vVERSION` already exists locally or on `origin` at another commit, or the working tree is dirty.
- `--dry-run` validates everything and prints the plan (version, tag, notes source) plus a warning if the working tree is dirty, without touching the repository or GitHub.
- Publishing creates the annotated tag `vVERSION`, pushes it to the `origin` remote, and runs `gh release create vVERSION --title vVERSION --generate-notes` (or `--notes-file "$RELEASE_NOTES_FILE"` when set); `gh` must be installed and authenticated (`gh auth login`), and the working tree must be clean.
- Publication is resumable: if a run pushes the tag but `gh release create` fails, re-running the script validates the tag target and publishes the missing release instead of aborting; an already-published release is a no-op.
